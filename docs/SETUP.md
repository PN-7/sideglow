# Sideglow 0.5.0-preview.7 — 화면별 연결 안내

Sideglow는 기존 `WHISPER1:` 코드와 `.whisper.json` 파일도 계속 읽습니다. 새로 내보내는 `SIDEGLOW1:` 코드·`.sideglow.json` 파일을 친구에게 전달할 때는 친구도 새 버전을 사용해야 합니다.

처음에는 **설정 → 처음 연결 / 로그인…**에서 시작합니다. 준비하는 사람 한 명이 Discord 웹사이트에 앱을 만들고, 친구들은 받은 연결 코드를 붙여 넣거나 앱 ID·채널 링크·선택적인 전송 웹후크를 입력한 뒤 자기 계정으로 로그인합니다. **설정 파일은 필수가 아닙니다.** 연결을 마친 뒤에는 **채널·웹후크 수정…**이나 **채널 탭**에서 주소만 바로 바꿀 수 있습니다.

**먼저 확인할 제한:** 이 버전의 B 연결은 새 Discord 앱에 필요한 권한이 실제로 허용되는지 아직 검증되지 않은 미리보기입니다. Discord는 [`rpc` 권한을 승인된 파트너용으로 설명](https://docs.discord.com/developers/topics/oauth2)합니다. [RPC 테스터 안내](https://docs.discord.com/developers/topics/rpc)가 모든 새 앱의 읽기 권한을 보장하지는 않습니다. **Public Client가 없거나 채팅 읽기 권한이 거부되면 그 단계에서 멈추세요.** 웹후크를 먼저 만들거나 친구들에게 파일을 나누어도 이 권한 문제는 해결되지 않습니다.

아래 위치는 공식 문서에서 확인한 메뉴와 이 버전의 코드에 맞춘 안내입니다. 로그인한 Developer Portal 화면, 실제 Windows 연결 안내, 소유자·친구 계정의 Discord 접속은 이 개발 환경에서 직접 실행해 확인하지 못했습니다. 수행한 검증은 [VALIDATION.md](VALIDATION.md)에 있습니다.

## 어느 화면에서 무엇을 하나요?

| 장소 | 하는 일 |
|---|---|
| **Sideglow** | 앱 ID·채널 링크·웹후크 직접 입력, 각자의 로그인, 수신·전송 상태 확인, 채널 탭 관리. 친구용 파일은 선택 사항 |
| **브라우저의 Discord Developer Portal** | 처음 준비하는 사람이 앱을 만들고, Public Client와 로그인 복귀 주소를 등록 |
| **Discord PC 앱** | 자기 계정으로 실행해 둠. Sideglow가 이 앱을 통해 채널 메시지를 읽음 |
| **Discord의 서버 설정** | 읽기가 확인된 뒤 전송용 웹후크를 만들고 대상 채널을 지정 |
| **브라우저의 Discord 승인 화면** | 각자가 자기 계정으로 Sideglow에 필요한 권한 승인 |
| **Sideglow → AI 번역 설정…** | 선택 사항. 번역 담당자 한 명이 API 제공사·주소·키·모델을 준비. Discord 로그인과 별도 설정 |

이 연결에는 별도 중계 서버를 운영하지 않습니다. Discord PC 앱은 실행해 두어야 합니다. 기존 번역 봇이 채널에 올린 번역 답글도 같은 채널의 메시지로 받습니다.

## 내가 처음 준비하기

Discord PC 앱에 로그인한 뒤 Sideglow를 일반 실행하세요. `--demo`나 `start-demo.cmd`는 화면 예제용이므로 실제 연결 전에 닫습니다.

Sideglow에서 **설정 → 처음 연결 / 로그인… → 내가 처음 준비하기**를 선택합니다.

### 1 / 4 · Discord 앱 만들기

**작업 장소: 브라우저의 Developer Portal → 다시 Sideglow**

1. Sideglow의 **개발자 페이지 열기**를 누릅니다. 열리는 주소는 [Discord Developer Portal의 Applications](https://discord.com/developers/applications)입니다.
2. 사용할 앱이 있으면 선택합니다. 새로 만들 경우 새 애플리케이션을 만들고 이름을 지정합니다. 이 이름은 나중에 로그인 승인 화면에서 친구가 보게 될 앱 이름입니다.
3. 앱의 왼쪽 메뉴에서 **General Information**을 선택하고 **Application ID**를 복사합니다.
4. Sideglow로 돌아와 앱 ID 입력란에 붙여 넣고 다음 화면으로 이동합니다.

Application ID는 앱을 구분하는 공개 숫자이며, **Client ID와 같은 값**입니다. 위치는 [Discord의 ID 안내](https://support-dev.discord.com/hc/en-us/articles/360028717192-Where-can-I-find-my-Application-Team-Server-ID)에 나와 있습니다. 여기서 필요한 것은 앱 ID입니다. B만을 위해 Bot을 추가하거나 봇 토큰을 복사할 필요는 없습니다.

### 2 / 4 · 로그인 주소 등록

**작업 장소: 브라우저의 같은 앱 → OAuth2**

이 화면의 주소는 **Discord 로그인 승인을 마친 브라우저가 이 PC의 Sideglow에 결과를 전달하는 주소**입니다. 이것을 Redirect URI 또는 redirect URL이라고 부릅니다. 서버를 빌리거나 인터넷에 웹사이트를 만드는 절차가 아닙니다.

1. Sideglow의 **OAuth2 설정 열기 (앱 선택)**를 누릅니다. [공식 OAuth2 앱 선택 화면](https://discord.com/developers/applications/select/oauth2)이 열립니다. **1단계에서 앱 ID를 가져온 것과 같은 앱**을 고르세요. 이미 앱을 열어 놓았다면 왼쪽 메뉴의 **OAuth2**로 이동해도 됩니다.
2. OAuth2 화면의 **Client information**에서 **Public Client**를 켭니다. **Bot 메뉴의 Public Bot은 다른 설정**입니다.
3. Sideglow의 **주소 복사**를 누릅니다.
4. **브라우저의 OAuth2 화면**으로 돌아가 **Redirects**에 복사한 주소를 추가하고 변경 사항을 저장합니다.

   ```text
   http://127.0.0.1:43821/callback
   ```

5. Sideglow로 돌아와 **웹사이트에서 주소를 등록하고 Public Client를 켰습니다.** 확인란을 선택하고 **다음: 수신 확인**을 누릅니다. 이 확인란은 사용자가 준비를 마쳤다는 표시입니다. Sideglow가 웹사이트 설정을 자동으로 확인한 것은 아니며, 주소 복사나 확인란 선택만으로 Discord 웹사이트에 등록되지는 않습니다.

`http`, `127.0.0.1`, `43821`, `/callback`을 모두 그대로 사용합니다. `localhost`나 다른 포트로 바꾸지 마세요. Discord 문서의 일반 예시인 `http://127.0.0.1/callback`과도 다릅니다. Sideglow는 **43821 포트를 포함한 주소**를 사용합니다. Client Secret을 입력하거나 배포하지 않습니다.

**Public Client 항목이 보이지 않으면 여기서 멈춥니다.** Discord의 [현재 시작 안내](https://docs.discord.com/developers/discord-social-sdk/getting-started/using-c%2B%2B)와 [공식 샘플](https://github.com/discord/social-sdk-unity-sample/blob/main/README.md)은 OAuth2에 이 설정을 안내하지만, Social SDK 준비 순서가 다르게 서술되어 있고 모든 새 앱에서 이 항목이 제공되는지는 확인되지 않았습니다. Social SDK 등록이 Sideglow의 기존 채널 읽기 권한을 해결한다는 근거도 없습니다. 이 문서는 임의의 게임 정보 등록이나 다른 앱의 자격증명 사용을 해결책으로 안내하지 않습니다.

### 3 / 4 · 채팅 수신 확인

**작업 장소: Discord 채널 → Sideglow → 브라우저의 로그인 승인 화면**

이 단계에서는 **웹후크가 필요하지 않습니다.** 먼저 읽기가 실제로 가능한지 확인합니다.

1. Sideglow의 **Discord 웹 열기**로 웹 Discord를 열고 대상 서버의 텍스트 채널을 선택합니다.
2. 브라우저 주소 표시줄에서 해당 채널 주소를 복사합니다. 형태는 다음과 같습니다.

   ```text
   https://discord.com/channels/서버ID/채널ID
   ```

3. Sideglow의 채널 링크 입력란에 붙여 넣습니다. `discord.gg/...` 초대 링크나 `.../api/webhooks/...` 주소는 채널 링크가 아닙니다.
4. **Discord PC 앱이 실행 중이고 같은 계정으로 로그인되어 있는지 확인**합니다. 브라우저에서 채널이 열려 있는 것만으로는 부족합니다.
5. **브라우저에서 로그인하고 수신 확인**을 누릅니다. 브라우저에서 앱 이름·계정·요청 권한을 확인하고 승인합니다.
6. Sideglow로 돌아와 수신 확인 결과를 기다립니다. 로그인 승인만으로 성공 처리하지 않습니다. 프로그램은 Discord PC 앱의 인증, 지정 채널 구독, 초기 채널 조회까지 확인합니다.
7. 수신이 확인되면 다음 단계로 이동합니다. 실제 채널에서 새 메시지가 생길 때 Sideglow에도 표시되는지 확인하세요. 비어 있는 채널은 초기 기록도 비어 있을 수 있습니다.

권한 오류가 나오면 웹후크 단계로 진행하지 않습니다. 앱의 승인 조건과 테스터 등록 가능 여부를 확인해야 합니다. 필요한 경우 앱을 준비한 사람이 Developer Portal의 **App Testers**에서 친구를 초대하고 친구가 초대를 수락합니다. Discord는 [RPC 개발 중 승인된 테스터, 최대 50명](https://docs.discord.com/developers/topics/rpc)을 안내하지만, 이를 `rpc`·`messages.read` 허가의 보장으로 볼 수는 없습니다. [App Testers 메뉴 안내](https://support-dev.discord.com/hc/en-us/articles/21204493235991-How-Can-Users-Discover-and-Play-My-Activity)는 Activity 문서이므로 그 문서의 Activity 실행 절차를 Sideglow에 적용하지 마세요.

Sideglow는 외부 브라우저의 OAuth + PKCE로 `identify rpc messages.read`를 요청합니다. 프로그램은 선택한 한 채널만 구독하지만, Discord의 `messages.read` 동의 범위 자체가 그 채널 하나로 제한된다는 뜻은 아닙니다. 규격은 [OAuth2 문서](https://docs.discord.com/developers/topics/oauth2)와 [공식 인증 서버 메타데이터](https://discord.com/.well-known/oauth-authorization-server)에 있습니다.

### 4 / 4 · 메시지 전송 준비

**작업 장소: Discord의 서버 설정 → 다시 Sideglow**

수신 확인이 끝난 뒤에 진행합니다. 웹후크는 Sideglow에서 작성한 메시지를 Discord 채널로 보내는 주소입니다. 채널의 메시지를 Sideglow로 보내 주는 주소가 아닙니다.

1. Discord에서 대상 서버를 엽니다. 서버 이름의 메뉴에서 **서버 설정 / Server Settings → 연동 / Integrations**으로 이동합니다.
2. 웹후크 항목에서 **Create Webhook**으로 새 웹후크를 만들거나, 이 용도로 사용할 기존 웹후크를 엽니다.
3. 웹후크의 대상 채널을 **3단계에서 읽기를 확인한 것과 같은 채널**로 지정합니다. 이름을 정하고 변경 사항을 저장합니다.
4. **Copy Webhook URL**을 눌러 복사합니다. 이 위치와 채널 선택은 [Discord의 공식 웹후크 안내](https://support.discord.com/hc/en-us/articles/228383668-Intro-to-Webhooks)에 나와 있습니다. 만들기·관리에는 해당 권한이 필요합니다.
5. Sideglow로 돌아와 전송용 웹후크 URL 입력란에 붙여 넣습니다.
6. **전송 채널 확인하고 연결**을 누릅니다. 앞 단계에서 저장된 로그인으로 다시 연결하고 웹후크의 종류·대상 채널을 조회합니다. **이 버튼은 확인용 메시지를 보내지 않습니다.**
7. 수신과 전송 준비가 모두 확인되면 **완료**를 누릅니다. 친구에게 앱 ID·채널 링크·웹후크 URL을 직접 전달하면 됩니다. 파일로 묶고 싶을 때만 완료 전에 **친구용 설정 파일 저장…**을 사용합니다.

웹후크 확인이 실패해도 채팅 수신은 유지됩니다. 전송은 막혀 있으며 주소를 수정해 다시 확인할 수 있습니다. 이 단계는 실제 메시지 POST 성공까지 검증하는 단계는 아닙니다. 실제 발신은 사용자가 채팅을 작성해 보낼 때 발생합니다.

기본 파일 이름은 **`Sideglow-connection.sideglow.json`**입니다. 이 파일에는 **앱 ID·채널 링크·전송용 웹후크 URL이 들어 있습니다. 웹후크 URL은 평문이며 파일 전체가 암호화되어 있지 않습니다.** 해당 채널에 보낼 권한을 주는 파일이므로 신뢰하는 친구에게 전달하세요. 자신의 Discord 로그인 토큰, 게임 경로, 글꼴·위치 같은 화면 설정, 중계 접속 키는 들어 있지 않습니다.

친구에게는 실행 파일과 세 값을 전달합니다. 앱 ID는 공개 번호이고, 채널 링크는 수신 대상을 가리키며, 웹후크는 전송 권한이 있는 비밀 주소입니다. 듣기만 할 친구에게는 웹후크를 주지 않아도 됩니다. 앱 소유자가 아닌 친구 한 명도 아래 절차로 실제 수신이 가능한지 먼저 확인하세요. 준비한 사람의 성공이 다른 계정의 권한까지 보장하지는 않습니다.

## 연결 코드를 복사해서 전달하기

설정의 연결 방식 옆 **연결 공유 코드…**를 열고 **현재 설정 코드 복사**를 누릅니다. 현재 설정 초안의 앱 ID·채널·웹후크를 한 개의 코드로 복사합니다. 코드 창을 열거나 복사하는 것만으로 설정을 저장하거나 Discord로 메시지를 보내지 않습니다.

친구는 같은 창 또는 처음 연결 안내의 친구 화면에서 **연결 코드 붙여넣기…**를 사용합니다. **코드 붙여넣기 → 미리보기 확인 → 설정에 채우기** 후 메인 설정에서 저장하거나 명시적인 로그인 단계로 진행합니다. [CONNECTION-CODE.md](CONNECTION-CODE.md)에 자세한 순서를 정리했습니다.

코드는 암호화가 아니며 웹후크가 포함되면 그 전송 자격증명도 포함합니다. 자신의 OAuth 토큰·번역 API 키는 포함하지 않습니다. 기존 JSON 파일은 계속 선택적으로 사용할 수 있습니다.

## 친구에게 받은 코드·링크로 연결

**친구는 Developer Portal에서 새 앱이나 봇을 만들거나 Redirect URI를 등록하지 않습니다.** 준비한 사람에게 받은 앱 ID와 링크를 입력하고, 자신의 계정으로 로그인합니다. JSON 파일을 다운로드할 필요는 없습니다.

1. 받은 실행 파일을 풀고 Sideglow를 일반 실행합니다. Discord PC 앱도 실행하고 자신이 사용할 계정으로 로그인합니다.
2. **설정 → 처음 연결 / 로그인… → 친구에게 받은 코드·링크로 연결**을 누릅니다.
3. 코드를 받았다면 **연결 코드 붙여넣기…**로 세 칸을 채웁니다. 또는 **Discord 앱 ID·Discord 채널 링크·메시지 전송용 웹후크 URL**을 각각 붙여 넣습니다. 같은 앱 ID가 이미 저장되어 있으면 유지하고 두 링크만 바꾸면 됩니다. 웹후크를 비우면 수신 전용으로 사용합니다.
4. 파일로 받았다면 대신 **JSON 파일 불러오기…**에서 `.sideglow.json`을 열어 세 칸을 채울 수 있습니다. 이 버튼은 전체 설정·다른 탭·친구의 로그인 정보를 가져오지 않으며, 로그인도 시작하지 않습니다.
5. **브라우저에서 Discord 로그인**을 누릅니다. 앱 이름과 로그인한 계정을 확인하고 승인합니다. 브라우저 계정과 Discord PC 앱 계정이 다르면 사용할 계정을 맞춘 뒤 다시 진행하세요.
6. 수신 상태와, 웹후크를 넣었다면 전송 준비 상태를 확인하고 **완료**를 누릅니다. 웹후크를 비운 수신 전용도 완료할 수 있습니다. 오류가 나오면 내용을 앱을 준비한 사람에게 알려 주세요. 자기 앱을 새로 만드는 것으로 해결할 필요는 없습니다.
7. 일반 설정으로 돌아와 **실행 중인 앱 및 단축키**에서 실제 게임을 고르고 저장합니다. 새로 실행한 게임은 **목록 새로고침**으로 반영합니다.

전달받은 코드·링크·파일에는 친구의 로그인 정보가 없으므로 **각자의 로그인 승인이 필요합니다.** 테스터 등록·초대 수락이 요구되는 앱이라면 앱을 준비한 사람이 그 절차를 안내해야 합니다. 앱 ID와 링크를 받았다는 사실만으로 Discord가 읽기 권한을 부여하지는 않습니다.

## 연결한 뒤 채널·웹후크만 바꾸기

**설정 → 채널·웹후크 수정…**에서 현재 탭 이름·채널 링크·웹후크를 바로 고칩니다. 편집 창에서 **적용**을 누르고 기본 설정의 **저장**까지 누르면 실제 연결에 반영합니다. 기본 설정을 취소하면 아직 저장하지 않은 연결 변경도 버립니다. 이 편집 창은 입력값을 확인하는 화면이며, 여는 것만으로 새 로그인·메시지 전송을 시작하지 않습니다.

같은 앱을 사용하면 앱 ID를 그대로 둡니다. 앱 ID는 모든 탭이 함께 사용하는 공개 번호이므로 바꾸면 전체 탭의 로그인 기준이 달라집니다. 새 승인이 필요할 때 **처음 연결 / 로그인…**을 사용하세요. 채널이나 웹후크를 바꾸면 해당 탭의 공용 AI 번역 실행은 OFF가 되고, 앱 ID를 바꾸면 모든 탭의 번역 실행 선택을 OFF로 되돌립니다. 새 대상에서도 번역을 맡을 때 직접 다시 켭니다.

## 다른 채널을 탭으로 보관하기

1. **Alt+Tab으로 Sideglow를 선택 → +** 또는 **설정 → 채널 탭 → 추가…**를 누릅니다.
2. 탭 이름, 추가할 채널의 전체 링크, 그 채널의 웹후크를 붙여 넣습니다. 듣기만 할 탭은 웹후크를 비웁니다. **추가**를 누르면 기본 설정에 초안으로 들어갑니다.
3. 기본 설정에서 **저장**해야 탭을 추가하고 그 채널로 연결합니다. **취소**하면 저장하지 않은 탭 추가·수정·삭제를 버립니다.
4. 저장된 탭은 관리 화면에서 클릭하거나 **Ctrl+Tab / Ctrl+Shift+Tab**으로 전환합니다. 설정의 탭 목록에서는 **수정…·삭제**를 사용하고 마지막에 **저장**합니다. 탭은 최대 8개이며 마지막 한 개는 삭제 대신 수정합니다.

**선택한 탭만 수신·번역합니다.** 게임 중 표시·Enter 입력 중에는 탭 막대를 숨기며, 일반 입력 안내에는 선택한 채널 이름을 표시합니다. 전송 실패 초안을 복구한 경우에는 재전송 확인 안내가 우선입니다. 다른 탭에는 새 채팅 알림이 없고, 다시 선택하면 최근 기록을 조회합니다. 비활성 중 모든 대화의 수집이나 소급 번역은 하지 않습니다.

초안과 전송 실패 문장은 탭별로 보관하며, 비활성 탭의 메시지 보관은 최대 40개입니다. 모두 프로그램을 켜 둔 동안의 임시 메모리입니다. 원문 전송 결과를 기다리는 중에는 전환을 막고, 삭제·주소 변경으로 초안이 없어질 상황에는 그 탭에서 먼저 보내거나 비우도록 안내합니다. 전환 전에 Discord 게시를 시작한 번역은 원래 채널에 늦게 도착할 수 있으며 새 탭으로 옮겨 전송하지 않습니다.

## 연결 후 AI 번역 제공사 준비하기

Discord의 새 메시지 수신과 같은 채널의 전송 웹후크를 준비한 뒤, 번역을 맡을 한 사람만 **설정 → AI 번역 설정…**을 엽니다. **API 제공사**에서 **OpenAI / OpenAI 호환 서비스 / Anthropic / Gemini** 중 하나를 고릅니다. 공식 세 제공사의 **API 기본 주소**는 고정되어 있고, 호환 서비스만 HTTPS 기본 주소를 입력합니다.

**번역 API 키 · 이 Windows 계정에 보호 저장**에 그 연결용 키를 입력하고 **모델 ID · 직접 입력 가능**을 지정합니다. OpenAI 모델 프리셋과 Fast는 OpenAI에서만 사용합니다. Anthropic은 단일 workspace에 연결된 키, Gemini는 Google AI Studio의 Gemini API 키를 준비하며, 호환 서비스는 Bearer 인증·Chat Completions JSON mode와 `max_tokens`를 지원해야 합니다.

언어 A/B와 **이 PC에서 공용 번역 실행**을 설정한 뒤 AI 창의 **확인 → 기본 설정의 저장**을 마칩니다. 제공사·주소·키·모델은 모든 채널 탭이 공유하는 활성 설정 한 개입니다. **제공사나 주소를 바꾸면 새 연결용 키를 입력**하고, 같은 제공사·주소에서 모델만 바꿀 때는 키 입력란을 비워 기존 키를 유지합니다.

친구들은 API 키 없이 **받은 AI 번역 표시**를 켜면 됩니다. 연결 코드·파일에 번역 API 키나 제공사 설정은 넣지 않습니다. 타사 연동은 요청·응답 모의 테스트로 확인했으며 실제 타사 키로 API 호출을 수행한 것은 아닙니다. 정확한 지원 조건과 단계별 안내는 [API-PROVIDERS.md](API-PROVIDERS.md), 번역 담당 방식은 [AI-TRANSLATION.md](AI-TRANSLATION.md)를 확인하세요.

## 친구의 앱 테스터 초대와 수락

앱을 준비한 사람과 친구가 각각 한 번씩 진행합니다. 친구가 새 앱을 만들거나 앱 관리자 권한을 받을 필요는 없습니다.

1. **앱을 준비한 사람:** [Discord Developer Portal](https://discord.com/developers/applications)에 로그인하고, Sideglow에 입력한 앱 ID와 같은 앱을 선택합니다.
2. 왼쪽 **App Testers**를 엽니다. 초대할 친구가 Discord 친구 목록에 있는지 확인하고 **Discord 사용자 이름**으로 초대합니다. 서버에서 쓰는 별명이나 표시 이름과 구분하세요.
3. **친구:** 자신의 Discord 계정에 등록한 이메일에서 테스터 초대 메일을 열고 수락합니다. 초대를 보냈다는 사실만으로 수락이 완료되지는 않습니다. 메일이 없으면 등록 이메일과 스팸함을 확인합니다.
4. 브라우저와 Discord PC 앱이 **초대를 수락한 같은 계정**으로 로그인되어 있는지 확인합니다. Sideglow에서 **브라우저에서 Discord 로그인**을 다시 누르고 승인합니다.

등록 여부는 운영자의 같은 앱 **App Testers** 목록에서 초대한 계정을 확인하고, 수락 여부는 친구가 초대 메일을 통해 수락을 완료했는지 확인합니다. 다른 앱의 초대나 다른 계정의 수락은 이 앱에 적용되지 않습니다. 이 작업은 서버 초대·서버 역할 부여·웹후크 생성과 별개입니다.

[Discord 공식 RPC 문서](https://docs.discord.com/developers/topics/rpc#authorize)는 개발 중인 미승인 앱을 등록된 테스터로 제한하며 최대 50명을 설명합니다. [공식 App Testers 안내](https://support-dev.discord.com/hc/en-us/articles/21204493235991-How-Can-Users-Discover-and-Play-My-Activity)는 Developer Portal의 메뉴와 이메일 수락 절차를 설명합니다. 해당 지원 문서의 Activity 실행·Application Test Mode 설정은 Sideglow 연결 절차에 포함하지 않습니다.

테스터 수락 후에도 실패할 수 있습니다. [OAuth2 문서](https://docs.discord.com/developers/topics/oauth2)는 `rpc`를 승인된 파트너용 권한으로 설명하므로 테스터 초대가 모든 앱의 사용 허가를 보장하지는 않습니다. 친구만 실패하면 초대·수락·계정부터 확인하고, 앱을 만든 사람도 실패하거나 수락 후에도 같은 오류가 계속되면 앱의 권한과 로그인 설정을 확인합니다.

## 연결이 안 될 때

0.5.0-preview.3부터 인증 오류 아래에 `[OAuth2/authorize; invalid_scope]`처럼 단계와 오류 이름을 표시합니다. `authorize`는 브라우저 승인, `token`은 로그인 정보 교환, `refresh`는 저장된 로그인 갱신입니다. 서버가 보낸 임의 설명이나 토큰은 표시하지 않습니다. 이전 버전의 “이 앱은 RPC 채팅 읽기 권한을 사용할 수 없습니다”라는 한 문장은 `invalid_scope`와 `unauthorized_client`를 구분하지 않았으므로, 그 문장만으로 원인을 확정할 수 없습니다.

| 보이는 상황 | 확인할 위치와 다음 행동 |
|---|---|
| Developer Portal에 **Public Client**가 없음 | 같은 앱의 **OAuth2 → Client information**인지 확인합니다. Bot의 Public Bot으로 대체하지 않습니다. 해당 앱에서 제공되지 않으면 B 준비를 멈추고 앱의 지원·승인 조건을 확인합니다. |
| `authorize; invalid_scope` | 브라우저에서 요청한 권한이 거절되었습니다. 친구만 실패하면 위 **앱 테스터 초대와 수락** 절차와 로그인 계정을 확인합니다. 수락 후에도 실패하면 앱의 `rpc` 사용 허가를 확인해야 합니다. 아직 채널·웹후크 검사 전입니다. |
| `unauthorized_client` | 앱이 요청한 로그인 방식을 허용받지 못했습니다. 같은 앱 ID와 **OAuth2 → Public Client** 설정을 확인하고, 친구만 실패하면 테스터 수락과 계정도 확인합니다. 이 코드만으로 원인을 앱의 채팅 읽기 허가로 단정하지 않습니다. |
| `access_denied` | 승인을 취소했다면 다시 로그인해 허용할 수 있습니다. 허용했는데 거절되었다면 초대 수락·로그인 계정·앱 권한을 확인합니다. |
| `invalid_client` / `invalid_grant` | 전자는 앱 ID와 공개 클라이언트 인증 설정, 후자는 무효·만료된 승인 코드나 로그인을 확인합니다. `invalid_grant`는 Sideglow에서 로그인을 다시 시작합니다. |
| RPC 또는 채널 권한 오류 | 인증 이후 오류입니다. 브라우저와 PC 앱의 계정, 해당 계정의 채널 접근, 앱의 RPC·읽기 권한을 확인합니다. 이 단계도 웹후크 전송 권한과 별개입니다. |
| Redirect URI 오류 | 브라우저의 **같은 앱 → OAuth2 → Redirects**에 `http://127.0.0.1:43821/callback`이 저장되어 있는지 확인합니다. 앱 ID와 설정한 앱도 일치해야 합니다. |
| 43821 포트를 사용할 수 없음 | 다른 Sideglow 로그인 작업을 닫고 다시 시도합니다. 포트를 임의로 바꾸면 등록 주소와 맞지 않습니다. |
| Discord PC 앱을 찾지 못하거나 로컬 연결 실패 | Discord **PC 앱**을 실행하고 로그인합니다. 브라우저 Discord만 열어 두어서는 로컬 수신 연결이 만들어지지 않습니다. |
| 브라우저 승인 뒤 다른 계정·채널 접근 오류 | 브라우저와 Discord PC 앱의 계정, 그 계정의 대상 서버·채널 접근 가능 여부를 확인합니다. |
| 채팅은 보이는데 보낼 수 없음 | 수신 전용이거나 웹후크 확인이 실패했을 수 있습니다. **채널·웹후크 수정…**에서 같은 채널의 웹후크를 입력·저장합니다. 친구는 운영자에게 웹후크 주소·대상 채널을 확인해 달라고 요청하면 됩니다. 새 파일은 필요하지 않습니다. |
| 웹후크의 대상 채널이 다름 | Discord의 **서버 설정 → 연동**에서 웹후크의 채널을 확인합니다. Sideglow에서 읽는 채널과 같게 지정하거나 올바른 웹후크 URL을 가져옵니다. |
| 웹후크가 삭제되었거나 주소가 유효하지 않음 | 운영자가 사용할 웹후크를 다시 만들고 친구에게 새 주소를 전달합니다. 각자 **채널·웹후크 수정…**에서 바꾸고 저장합니다. 수신 권한과는 별개의 문제입니다. |
| 친구용 파일 저장을 할 수 없음 | 수신과 전송 준비가 모두 확인되어야 합니다. 오류나 연결 해제가 남아 있다면 먼저 해당 단계를 해결합니다. |
| 설정을 저장했는데 로그인 창이 안 뜸 | 일반 설정의 **저장**은 새 로그인을 시작하지 않습니다. 연결 안내의 **브라우저에서 로그인하고 수신 확인** 또는 **브라우저에서 Discord 로그인**을 누릅니다. |
| 탭을 추가했는데 아직 연결이 안 바뀜 | 편집 창의 **추가·적용**은 초안만 바꿉니다. 기본 설정 창의 **저장**까지 눌렀는지 확인합니다. |
| 초안 때문에 삭제·주소 변경을 저장할 수 없음 | 원래 탭으로 돌아가 남은 글을 보내거나 지웁니다. 복구할 실패 문장도 확인한 뒤 다시 변경합니다. 다른 채널로 초안을 옮겨 보내지는 않습니다. |

## 연결 정보의 저장과 공유 중단

이 PC의 설정은 `%LOCALAPPDATA%\Sideglow\settings.json`, 로그인 정보는 같은 폴더의 `rpc-session.bin`에 저장합니다. 로컬 파일의 웹후크 URL·OAuth 토큰은 Windows 계정의 DPAPI로 보호합니다. **이 보호는 다른 사람에게 전달하는 `.sideglow.json` 파일에는 적용되지 않습니다.**

### 저장 폴더 변경과 초기화

기본 저장 폴더는 `%LOCALAPPDATA%\Sideglow\`입니다. 앱은 기존 설정 폴더를 자동으로 찾거나 옮기지 않습니다. 기존 설정·로그인을 계속 쓰려면 업데이트한 실행 파일을 처음 열기 전에 같은 PC·같은 Windows 계정에서 다음 순서로 준비합니다.

1. Sideglow와 이전 실행 파일을 모두 완전히 종료합니다.
2. `%LOCALAPPDATA%`를 열어 기존 설정 폴더를 별도로 백업합니다. 이미 `Sideglow` 폴더가 있으면 두 폴더를 따로 보관하고 어느 설정을 사용할지 먼저 확인합니다. **설정 폴더끼리 덮어쓰거나 병합하지 않습니다.**
3. 사용하지 않을 폴더는 별도 이름으로 보관하고, 사용할 기존 설정 폴더의 이름을 `Sideglow`로 바꿉니다. `settings.json`과 `rpc-session.bin`을 포함한 폴더 전체를 유지한 뒤 앱을 실행해 설정과 로그인 상태를 확인합니다.

새 설정으로 초기화하려면 앱을 완전히 종료하고, `%LOCALAPPDATA%\Sideglow\`가 있다면 별도 이름으로 보관한 뒤 실행합니다. 기존 설정 폴더는 그대로 두어도 자동으로 읽지 않습니다. 초기화하면 Discord 재로그인·연결 설정·API 키 입력을 다시 해야 합니다. 폴더 이름 변경은 만료된 로그인이나 손상된 파일의 복구를 보장하지 않습니다.

### 로그아웃과 공유 중단

**이 PC 로그아웃**은 이 컴퓨터의 로그인 정보를 지우고 연결을 멈춥니다. 모든 탭의 수신 기록을 비우되 작성 중인 글과 실패 초안은 보존합니다. Discord의 원격 앱 승인까지 취소하려면 Discord 사용자 설정의 **승인한 앱 / Authorized Apps**에서 해제합니다.

웹후크 URL은 별도의 전송 권한입니다. 로그인 해제나 파일 삭제만으로 이미 전달한 주소가 무효가 되지 않습니다. 공유를 중단하거나 주소가 유출되면 Discord에서 웹후크를 삭제·재발급하고 함께 사용할 친구에게 새 주소를 전달하세요. 각자 해당 탭의 웹후크를 수정하면 되며 새 JSON 파일은 필요하지 않습니다. 웹후크 메시지는 개인 계정 메시지가 아니며, `Sideglow · 사용자 이름`이라는 표시 이름만으로 발신자의 계정을 인증할 수는 없습니다. [웹후크 API 안내](https://docs.discord.com/developers/resources/webhook)
