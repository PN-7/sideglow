# Sideglow — 내 API로 채널 번역하기

한 사람의 PC가 **현재 선택한 채널의 새 채팅**을 선택한 API로 번역하고, 같은 Discord 채널에 결과를 올릴 수 있습니다. **OpenAI, OpenAI 호환 서비스, Anthropic, Gemini** 중 하나를 사용하며 친구들은 API 키 없이 결과를 받습니다. 기존 번역 봇이 웹후크 메시지를 무시하던 문제를 이 기능에서 직접 처리합니다. 제공사별 주소·인증·모델 조건은 [API-PROVIDERS.md](API-PROVIDERS.md)에 정리했습니다.

**별도 중계 서버나 새 Discord 번역 봇은 필요하지 않습니다.** 대신 번역 담당자의 **Sideglow와 Discord PC 앱이 실행 중이고, 해당 채널에 연결되어 있어야 합니다.** 그 PC를 끄면 자동 번역도 멈춥니다. 기존 B 직접 연결의 수신 권한이 이미 작동해야 하며, 이번 기능이 Discord의 RPC 권한 제한을 해결하지는 않습니다.

## 먼저 알아둘 두 설정

| 설정 | 의미 | 기본값 |
|---|---|---|
| **이 PC에서 공용 번역 실행** | 내 키로 API를 호출하고 채널에 번역 결과를 전송합니다. 채널당 담당자 한 명만 켜세요. | 꺼짐 |
| **받은 AI 번역 표시** | 다른 PC가 채널에 올린 Sideglow AI 번역을 내 채팅창에 보여 줍니다. API 키가 필요하지 않습니다. | 켜짐 |

**Alt+Tab 관리 화면에는 두 토글이 있습니다.** 채팅 ON/OFF는 게임 위 표시와 입력 단축키를 조절하고, **번역 ON/OFF**는 이 PC에서 현재 탭의 공용 AI 번역 실행을 조절합니다. API 키·언어·채널을 한 번 준비한 뒤에는 번역 토글로 바로 전환할 수 있으며 탭별 실행 선택을 저장합니다. 이 버튼으로 다른 사람 PC의 실행이나 받은 번역 표시를 끄지는 않습니다. 채널 담당자는 한 사람만 켜세요.

## 여러 채널을 사용할 때

채널 탭은 최대 8개지만 **선택한 탭만 수신하고 번역**합니다. 탭을 추가하는 것은 다른 채널의 상시 번역 담당을 늘리는 기능이 아닙니다. 다른 탭으로 옮기면 이전 채널의 새 번역 작업을 멈추며, 비활성 탭에는 알림도 없습니다. 다시 선택했을 때 받아온 과거 기록은 소급 번역하지 않습니다.

새 탭과 채널·웹후크를 바꾼 탭은 번역 실행이 OFF입니다. API 제공사·주소·키·모델·언어·게임 용어는 모든 탭이 함께 사용하고, 실행 ON/OFF만 탭별로 기억합니다. 한 PC에 활성 번역 설정 한 개를 저장하며 제공사별 여러 키·프로필이나 자동 전환은 제공하지 않습니다. 공용 앱 ID를 바꾸면 모든 탭의 번역 실행 선택을 OFF로 되돌립니다. 탭 추가·주소 수정은 편집 창의 **추가·적용** 뒤 기본 설정의 **저장**까지 마쳐야 적용됩니다.

전환 전에 이미 제출한 API 요청은 처리·과금될 수 있고, Discord로 게시를 시작한 번역은 원래 채널에 늦게 올라올 수 있습니다. 이전 채널의 요청을 새 채널로 옮겨 보내지는 않습니다. 기존 번역 작업이 정리되기 전에는 새 탭의 작업자를 겹쳐 시작하지 않습니다.

## 번역 담당자: 한 번만 설정하기

지연 문제를 확인 중이면 먼저 아래의 **최근 번역 시간** 기록을 남기세요. 기존 Sideglow를 완전히 종료하고 새 실행 파일을 실행한 뒤 설정 창 제목이 **0.5.0-preview.7**인지 확인합니다. 기존 Discord 연결이 정상이라면 Developer Portal 설정을 다시 할 필요는 없습니다.

1. Discord PC 앱에 로그인하고, Sideglow에서 평소처럼 해당 채널의 새 메시지가 들어오는지 확인합니다.
2. Sideglow의 **설정 → AI 번역 설정…**을 엽니다.
3. **API 제공사**에서 **OpenAI / OpenAI 호환 서비스 / Anthropic / Gemini** 중 하나를 고릅니다. OpenAI·Anthropic·Gemini의 **API 기본 주소**는 공식 주소로 고정됩니다. **OpenAI 호환 서비스**를 고른 경우에만 서비스에서 안내한 HTTPS 기본 주소를 입력합니다. `/chat/completions`나 키·쿼리는 주소에 넣지 않습니다.
4. **번역 API 키 · 이 Windows 계정에 보호 저장**에 선택한 제공사에서 발급한 키를 붙여 넣고 **모델 ID · 직접 입력 가능**에 사용할 모델 ID를 입력합니다. OpenAI는 기존 기본값 `gpt-6-luna`와 모델 프리셋을 계속 사용할 수 있으며 **Fast 처리 사용**도 OpenAI 전용입니다. 타사로 바꿨다면 모델 ID를 그 제공사에서 사용할 수 있는 값으로 직접 바꿉니다. Anthropic은 단일 workspace에 연결된 키, Gemini는 Google AI Studio의 Gemini API 키를 준비하세요. [제공사별 준비 방법](API-PROVIDERS.md)을 참고하세요.
5. **언어 A / 언어 B**를 선택합니다. 기본값은 한국어 / 영어입니다. A 문장은 B로, B 문장은 A로 번역하고 다른 언어는 A로 번역하도록 요청합니다. 예를 들어 한국어·영어 사용자끼리 대화할 때 담당자의 설정 한 쌍을 함께 사용합니다.
6. 필요한 경우 **게임 용어 설정**에 `궁극기 = ultimate`, `북쪽 문 = north gate`처럼 명칭을 적습니다. 비워도 됩니다. 최대 2,000 UTF-16 단위이며 일부 이모지는 두 단위로 셉니다.
7. **이 PC에서 공용 번역 실행**을 켭니다. 이 채널에서 다른 사람이 함께 켜고 있지 않은지 확인합니다.
8. **확인**을 누른 뒤, 원래 설정 창에서 **저장**을 누릅니다. 확인만 누르고 원래 설정 창을 취소하면 적용되지 않습니다.
9. 새로 보낸 짧은 문장으로 확인합니다. 켜기 전에 있던 채널 기록은 한꺼번에 번역하지 않습니다. 성공하면 채널에 `AI 번역` 명의의 결과가 올라오고, Sideglow에서는 원문과 묶여 표시됩니다.

### 로마자로 쓴 일본어

알파벳으로 일본어를 입력하는 사용자는 기본 **설정 → 내 메시지의 로마자 일본어 판별 → 저장**을 선택합니다. **기본값은 해제**이며, 일본어 사용자만 체크하고 다른 사용자는 해제한 채 사용할 수 있습니다. API 키나 공용 번역 실행을 켤 필요는 없습니다. 친구에게 받은 연결 코드를 적용해도 이 개인 선택은 유지됩니다.

**체크한 사용자가 Sideglow로 보낸 메시지이며 번역 언어 쌍에 일본어가 포함된 경우**에만 로마자 일본어용 추가 지침을 사용합니다. 한·일 쌍에서는 A/B의 순서와 관계없이 그 뜻을 한국어로 번역하도록 요청합니다. 로마자를 히라가나·가타카나로 옮기는 것으로 끝내지 않습니다. 체크를 해제해도 원래 일본어 문자·한국어·영어의 일반 번역과 언어 A/B 라우팅은 유지됩니다.

송신자와 번역 담당 PC를 **0.5.0-preview.7 이상으로 함께 업데이트**해야 합니다. 중계 방식을 쓴다면 중계 서버도 업데이트합니다. 일반 Discord 앱이나 이전 클라이언트에서 직접 보낸 메시지에는 이 개인 선택이 포함되지 않으므로 추가 지침은 적용되지 않습니다. 저장 후 새로 보내는 메시지부터 적용하며, 이미 전송 대기 중인 메시지는 보낼 때 선택한 값을 유지합니다.

아래는 **기대하는 동작 예시**이며 실제 API를 호출해 얻은 측정 결과는 아닙니다.

| 새로 입력한 원문 | 한·일 설정에서 기대하는 번역 |
|---|---|
| `arigatou` | 고마워 |
| `chotto matte` | 잠깐 기다려 |
| `daijoubu?` | 괜찮아? |
| `kore dou suru?` | 이거 어떻게 해? |

영어 문장 안의 일본 이름·용어만으로 문장 전체를 일본어로 강제 분류하지 않습니다. 여러 언어로 해석되는 짧은 단어와 약어는 해당 문장의 문맥으로 판단하도록 합니다. ASCII 여부나 단어 목록으로 로컬에서 언어를 확정하지 않으며, 실제 판별·표현 정확도는 선택한 모델에 따라 달라질 수 있습니다.

체크한 발신자의 일본어 언어 쌍에만 짧은 추가 지침을 기존 한 번의 번역 요청에 포함합니다. 체크를 해제한 발신자의 요청에는 해당 지침을 넣지 않습니다. 같은 원문이라도 개인 선택이 다르면 캐시를 구분합니다. 별도 언어 판별 요청·자동 재번역·새 작업자·이전 대화 전송은 추가하지 않습니다. 두 설정 언어 밖의 문장을 언어 A로 번역하는 기존 규칙은 유지합니다. 새 버전으로 재시작한 뒤 새로 수신한 번역 대상 메시지부터 적용하며, 이미 Discord에 게시된 과거 번역문을 자동으로 고치지는 않습니다.

### 키 유지와 제공사 변경

키 입력란은 다음에 열어도 비어 있습니다. 저장된 키를 보여 주지 않는 동작입니다. **같은 제공사·API 기본 주소에서는 아무것도 입력하지 않으면 기존 키를 유지**합니다. 따라서 모델·언어·게임 용어만 바꿀 때는 키를 다시 입력하지 않아도 됩니다. **제공사나 API 기본 주소를 바꾸면 그 연결에 사용할 키를 새로 입력**해야 하며 기존 키를 새 주소로 자동 전송하지 않습니다. 새 연결을 저장하면 이전 키를 제공사별로 따로 보관하지 않습니다. 기존 OpenAI 키는 공식 OpenAI 설정에서 계속 사용할 수 있습니다.

키를 교체하려면 새 키를 입력하고 저장하세요. **저장된 키 삭제**는 해당 PC의 저장 키를 지우고 공용 번역 실행도 끄는 설정입니다. 삭제 역시 확인·저장을 마쳐야 적용됩니다.

선택한 제공사로 해당 메시지의 원문과 선택한 언어·게임 용어가 전송됩니다. 호환 서비스를 선택하면 직접 입력한 주소가 수신 대상입니다. API 요청에 Discord 로그인 토큰이나 웹후크 URL을 넣지 않습니다. API 사용량은 입력한 키의 계정·프로젝트에 적용됩니다. 이용 가능한 크레딧·요금·모델 권한은 해당 제공사에서 확인하세요. OpenAI를 사용할 때는 [모델 문서](https://developers.openai.com/api/docs/models/gpt-6-luna.md)와 [요금 안내](https://developers.openai.com/api/docs/pricing.md)를 참고하세요.

### OpenAI 모델 목록과 직접 입력

**이 절의 프리셋·추론 설정·가격 설명은 API 제공사가 OpenAI일 때만 적용합니다.** 목록을 고르면 모델 ID와 설명이 바뀝니다. ID 입력란에 목록에 없는 이름을 직접 넣어도 됩니다. 목록은 2026-11-12 공식 문서를 기준으로 만든 후보이며, 내 계정이 사용할 수 있는 모델을 실시간 조회한 결과가 아닙니다. 다른 제공사는 모델 프리셋을 제공하지 않으며 해당 제공사의 모델 ID를 직접 입력합니다.

| 모델 | 프로그램의 추론 설정 | 선택할 때 볼 점 |
|---|---|---|
| [`gpt-6-luna`](https://developers.openai.com/api/docs/models/gpt-6-luna.md) | `none` | 기본값. 이 목록에서 토큰 단가가 가장 낮음 |
| [`gpt-6-sol`](https://developers.openai.com/api/docs/models/gpt-6-sol.md) | `none` | 별도 추론 없이 비교할 수 있으나 Luna보다 비쌈 |
| [`gpt-6.1-sol`](https://developers.openai.com/api/docs/models/gpt-6.1-sol.md) | `low` | 지원하는 최소 추론 단계. `none`은 지원하지 않음 |
| [`gpt-6-astra`](https://developers.openai.com/api/docs/models/gpt-6-astra.md) | `low` | 이 목록에서 가장 높은 토큰 단가. 품질 비교가 필요할 때 검토 |

큰 모델이나 최신 모델을 고른다고 짧은 게임 채팅의 번역이 더 빨라지는 것은 아닙니다. 같은 언어·길이의 문장으로 품질과 지연을 함께 비교하세요. 직접 입력하는 모델은 OpenAI Responses API와 구조화된 JSON 응답을 지원해야 합니다. 목록 밖 모델에는 추론 매개변수를 추측해서 추가하지 않습니다. 전체 목록과 변경 사항은 설정의 **공식 모델 목록** 또는 [OpenAI 모델 문서](https://developers.openai.com/api/docs/models)를 확인하세요.

### OpenAI Fast 처리: 비용을 올리고 비교하는 선택 기능

OpenAI를 선택한 상태에서 **Fast 처리 사용 · 목록 모델은 표준 요금의 2배**를 켜고 AI 창의 **확인**, 기본 설정의 **저장**을 마치면 다음 요청부터 Fast를 사용합니다. 기본값은 꺼짐입니다. 위 네 모델은 Fast의 토큰 단가가 해당 표준 처리의 2배이고, 직접 입력한 모델은 요금·지원 여부를 따로 확인해야 합니다. 공식 설명은 [Fast mode](https://developers.openai.com/api/docs/guides/fast-mode.md)와 각 모델의 가격 항목에 있습니다. 다른 제공사를 선택하면 이 옵션은 해제·비활성화되며 **Fast 처리 · OpenAI 전용**으로 표시합니다. 타사의 유사한 이름의 처리 옵션을 설정하는 기능은 아닙니다.

Fast는 별도 처리 등급으로 요청하는 기능입니다. 응답 전체 시간이 일정 비율로 줄어든다는 보장은 없으며, Discord 채널 확인과 게시 시간은 그대로 남습니다. 모델·계정·지역 지원 조건에 따라 요청이 거절될 수 있습니다. Fast로 요청해도 서비스가 표준으로 처리할 수 있으므로 **최근 번역 시간…**에 요청한 방식과 실제 응답의 방식을 따로 표시합니다. 실제 값이 없으면 추측하지 않고 미보고로 표시합니다.

Fast를 끄면 명시적으로 표준 처리를 요청합니다. 이 PC에서 껐는데 API 프로젝트의 기본 설정 때문에 Fast가 자동 적용되는 일을 피하기 위한 동작입니다. 지원하지 않는 모델에서 실패했다고 다른 유료 모델이나 처리 등급으로 자동 재요청하지 않습니다. 이번 버전에서 실계정으로 Fast의 단축 폭을 재측정하지는 않았습니다.

## 친구들: API 키 없이 사용하기

친구도 새 Sideglow 실행 파일로 업데이트합니다. [저장 폴더 안내](SETUP.md#저장-폴더-변경과-초기화)에 따라 기존 설정 폴더의 수동 이름 변경을 마친 경우 기존 채널 연결을 이어서 사용하며, 이전 단일 채널 설정은 기본 탭으로 읽습니다. 처음 연결하는 친구는 **설정 → 처음 연결 / 로그인… → 친구에게 받은 링크로 연결**에서 공유 앱 ID·채널 링크·선택적인 웹후크를 직접 입력하고 자기 계정으로 승인합니다. JSON 파일은 선택 사항입니다. 자세한 순서는 [연결 안내](SETUP.md)에 있습니다.

- **이 PC에서 공용 번역 실행**은 꺼 둡니다.
- **받은 AI 번역 표시**는 켜 둡니다.
- API 키를 입력하거나 번역 API 제공사 계정을 준비할 필요가 없습니다.

친구용 연결 코드·파일에는 번역 API 키·제공사 설정과 게임 용어·번역 실행 설정을 넣지 않습니다. 링크 직접 입력이나 선택적인 파일 가져오기로 친구용 연결을 적용하면 해당 연결의 번역 실행은 꺼집니다. 로컬에 저장된 키와 언어 설정은 유지하므로, 새 채널에서도 담당하려면 직접 실행 설정을 켜고 저장하세요. 수신 전용 친구는 공용 번역 실행에 필요한 웹후크를 준비하지 않아도 됩니다.

이 기능에 추가 Discord 개발자 앱이나 봇이 필요한 것은 아닙니다. 기존 B 연결의 각자 로그인 및 앱 권한 조건은 그대로입니다. 여러 PC가 동시에 담당할 때 한 대를 자동 선출하는 기능은 없으므로, 담당자를 한 명 정해야 합니다. 같은 번역이 이미 도착하면 중복 작업을 걸러내지만 동시에 시작된 여러 PC의 API 비용이나 채널 중복 게시를 완전히 막는 잠금 장치는 아닙니다.

## 어떤 메시지를 번역하나요?

**수신은 기존 Discord PC 앱의 채널 이벤트로 처리합니다.** 웹후크 URL은 채널의 모든 메시지를 읽는 주소가 아니라 메시지를 보내는 주소입니다. 이번 기능 때문에 새 웹후크 수신 서버를 여는 것은 아닙니다.

번역 대상은 연결한 채널의 새 일반 사용자 텍스트와 **현재 Sideglow 설정에 등록된 전송 웹후크**의 텍스트입니다. 따라서 Sideglow에서 보낸 메시지도 번역할 수 있습니다. 다른 봇과 다른 웹후크의 글은 제외합니다. 기존 MohCitrus 같은 번역 봇이 별도로 답하면 그 답변은 기존 방식으로 표시될 수 있지만 새 AI 번역 요청에는 넣지 않습니다. 같은 채널에서 두 번역 기능을 동시에 사용할 필요는 없습니다.

- 첨부 파일, 이미지, 링크 미리보기 자체는 번역하지 않습니다. 원래 텍스트만 사용합니다.
- Sideglow의 AI 번역 결과는 다시 번역하지 않습니다.
- 같은 메시지의 반복 수신과 링크 미리보기 갱신은 새 API 요청으로 만들지 않습니다.
- 초기 연결과 재접속 때 받은 과거 기록은 자동 번역하지 않습니다. 끊겨 있던 동안의 채팅도 초기 기록으로 들어오면 건너뜁니다.
- 원문 내용이 실제로 수정되면 새 내용으로 번역할 수 있습니다. 수정·삭제·채널 변경·재접속으로 무효가 된 대기 작업과 늦은 결과는 버립니다.
- 번역된 글이 Discord의 한 메시지 길이 제한을 넘으면 잘라서 전송하지 않고 건너뛴 이유를 표시합니다.

Discord에는 **원문으로 가는 링크 + 번역문**이 일반 웹후크 메시지로 올라갑니다. Discord 자체의 네이티브 ‘답글’ 객체를 만드는 기능은 아닙니다. 새 Sideglow는 이 링크의 원문 ID와 내용 버전을 읽어 같은 원문 아래에 표시합니다. 원문이 수정·삭제되거나 현재 보관 기록에서 사라지면, 맞지 않는 AI 번역은 Sideglow 화면에서 숨깁니다. 이미 Discord에 올라간 번역문을 자동 삭제·수정하지는 않습니다.

Sideglow의 AI 번역 앞에 붙던 `JA ·`, `KO ·` 같은 언어 표시는 생략합니다. 번역 방향·원문 연결·중복 판정은 그대로 유지합니다. 원문과 기존 봇이 직접 작성한 메시지 내용을 임의로 고치는 기능은 아닙니다.

선택한 탭의 보관 기록은 최대 200개 메시지 객체이며, 떠난 탭은 최대 40개만 메모리에 남깁니다. 원문과 번역·답글도 각각 한 메시지이므로 화면에 보이는 대화 묶음 수와 같지 않습니다. 긴 대화에서는 원문이 기록 밖으로 나가 대응하는 번역도 오버레이에서 보이지 않을 수 있습니다. Discord 채널의 메시지는 그대로 남습니다.

## 번역문 크기와 색을 따로 바꾸기

기본 설정의 **번역문 별도 스타일**을 켜고 **크기 pt**를 8~48로 입력한 뒤 **번역문 색상…**에서 색을 고릅니다. 끄면 번역문도 본문 크기와 색을 따릅니다. 별도 글꼴을 고르는 기능은 아니며 시스템 글꼴은 본문과 함께 사용합니다.

이 스타일은 원문 아래에 묶어 표시하는 **Sideglow AI 번역과 봇 답글**에 적용합니다. 일반 사용자의 답글과 원문은 본문 스타일을 유지합니다. 봇의 답글이라는 표시를 기준으로 구분하며, 일반 텍스트의 언어를 추측해 번역문으로 분류하지 않습니다.

크기·색·켜기/끄기는 채팅창에서 바로 미리 보입니다. **저장**하면 유지하고, **취소·닫기**면 이전 모양으로 돌아갑니다. 표시만 바꾸는 기능이므로 번역 실행·API 요청이나 다른 사람의 화면을 바꾸지 않습니다.

## 속도와 자원 사용

**원문 전송과 번역 요청은 별도 작업입니다.** API 응답을 기다리느라 채팅 입력이나 원문 전송을 대기시키지 않습니다. 원문을 먼저 보낸 뒤 번역이 따로 도착하므로, 게임 중 짧은 대화에서도 원문은 먼저 읽을 수 있습니다.

번역 담당 기능을 끈 PC는 번역 작업 스레드·대기열·캐시·번역 API HTTP 세션을 만들지 않고 API 키를 복호화하지 않습니다. 실행 파일에 번역 코드와 설정 필드는 포함되고, 받은 결과를 묶어 표시하는 처리는 남습니다. 따라서 ‘모든 추가 비용이 정확히 0’이라고 표현하지는 않습니다. 별도 웹뷰나 로컬 AI 모델을 로드하는 구조는 아닙니다.

켜 둔 PC는 **선택한 채널에서 최대 두 건을 동시에 처리**합니다. 탭마다 두 작업자를 추가하는 구조가 아니며, 프로그램의 번역 담당 하나가 현재 탭을 처리합니다. 각각 독립된 통신 세션을 쓰되 오류 대기·중단 상태를 공유합니다. 번역 대기열은 16건, 추적 기록은 최대 400건이며 오래된 대기 요청은 버립니다. 요청은 큐에 들어온 뒤 30초가 지나면 유효하지 않은 것으로 처리하므로 혼잡한 채널의 모든 메시지 번역을 보장하지 않습니다. 유휴 상태에서는 번역 API를 반복 조회하지 않고 새 작업을 기다립니다.

같은 설정에서 **번역이 완료된 완전히 같은 문장**은 최대 64건·5분 동안 메모리에서 재사용합니다. 재사용은 새 번역 API 요청과 토큰 사용을 만들지 않지만 새 원문에 맞는 링크로 Discord 게시·대상 확인은 수행합니다. 대소문자·공백과 발신자의 로마자 옵션까지 같아야 적용하고, 제공사·API 기본 주소·모델·Fast·언어·용어·채널·키 설정을 바꾸거나 프로그램을 종료하면 해당 캐시는 사라집니다. 동시에 처음 들어온 동일 문장의 API 요청을 하나로 합치는 기능은 아닙니다.

**공용 번역 실행을 끄면** 새 작업을 받지 않고 이전 작업을 취소 상태로 만듭니다. 이미 Windows 통신 호출 중인 작업은 반환할 때까지 정리 중일 수 있습니다. 그동안 새로운 번역 작업자를 중복 실행하지 않습니다. **이미 번역 API 제공사나 Discord에 제출된 HTTP 요청의 처리·요금·게시를 되돌리는 것은 보장하지 않습니다.**

상단 **번역 OFF**는 먼저 이 PC의 번역 실행을 중지합니다. 설정 파일 저장까지 실패한 경우에는 꺼짐을 저장하지 못했다고 안내하므로, 다음 실행 전에 저장 상태를 확인하세요. ON은 필요한 연결·API 설정이 유효하고 저장에 성공해야 적용됩니다.

이번 변경의 CPU·메모리와 번역 시간을 실제 Windows PC에서 전후 비교한 결과는 아직 없습니다. 기존 두 작업자의 병렬 처리는 밀린 대기열을 줄이고 재사용은 반복 문장의 새 API 요청을 없애는 동작입니다. **처음 번역하는 문장 한 건의 API 응답 자체가 4~6초라면 이 구조만으로 1초 이하가 된다고 말할 수 없습니다.** OpenAI 기본 `gpt-6-luna`의 추론 설정은 이전부터 `none`입니다. OpenAI의 모델 프리셋·선택적 Fast, 모든 제공사의 모델 직접 입력과 상세 시간 측정을 유지합니다.

### preview.4 이후 지연 증가를 느낄 때

이 절은 OpenAI만 지원하던 preview.3~preview.5의 변경과 측정 해석을 기록합니다. preview.4에서 로마자 일본어를 문자 체계와 무관하게 판별하고 의미를 번역하도록 지침을 추가했습니다. 배포본 소스를 비교하면 지침 문자열의 크기는 다음과 같습니다.

| 버전 | 공통 지침 | 일본어 전용 추가 지침 | 일본어 쌍 합계 |
|---|---:|---:|---:|
| 0.5.0-preview.3 | 502바이트 | 없음 | 502바이트 |
| 0.5.0-preview.4 | 580바이트 | 379바이트 | 959바이트 |
| 0.5.0-preview.5 | 544바이트 | 192바이트 | 736바이트 |

위 수치는 **지침 문자열의 UTF-8 바이트 수**입니다. 전체 HTTP 요청 크기·입력 토큰 수·실제 응답 시간이나 모델 품질 측정치가 아닙니다. preview.5는 같은 처리 방침을 더 짧게 표현해 일본어 쌍의 지침을 preview.4보다 약 23% 줄였습니다. preview.3보다 길어졌던 것이 체감 지연의 원인인지, 이번 축소가 얼마나 빨라지는지는 실계정 전후 비교가 필요합니다. [OpenAI의 지연 최적화 안내](https://developers.openai.com/api/docs/guides/latency-optimization)는 먼저 실제 대기 구간과 입력·출력·캐시·모델·처리 등급을 비교하도록 안내합니다.

preview.3 → preview.4 → preview.5 사이에 모델 선택·추론 설정·처리 등급·API 호출 수·출력 상한·작업자 2개·캐시 64건/5분·Discord 확인/게시 경로는 바뀌지 않았습니다. Enter 수정은 원문 전송을 먼저 큐에 넣고 게임 포커스 복귀만 키 해제까지 보류합니다. 번역 API를 키 해제까지 대기시키는 단계는 추가하지 않았습니다.

**느려진 직후, 업데이트하거나 재시작하기 전에 설정 → 최근 번역 시간… 화면을 남기세요.** 기록은 최근 한 건만 메모리에 보관합니다. 대기열이 늘었는지, API 전체가 늘었는지, Discord 확인·게시 또는 UI 이벤트 전달이 늘었는지를 먼저 구분할 수 있습니다. 모델·실제 처리 등급·입력/출력/추론 토큰·재사용 여부도 함께 비교합니다. 한 번의 결과만으로 원인을 확정하지 않습니다.

재시작하면 완료 문장의 로컬 캐시와 기존 HTTP 세션이 없어집니다. 이전에는 캐시에서 재사용한 문장이고 이후에는 API를 새로 호출한 문장이었다면 직접 비교할 수 없습니다. 이는 가능한 비교 조건의 차이이며 이번 지연의 확인된 원인은 아닙니다. 캐시가 아닌 같은 조건의 새 문장 여러 건으로 비교하는 편이 좋습니다.

아래의 **전체**는 번역 대기열 진입 이후만 측정합니다. Enter를 누른 시점부터 번역이 보일 때까지의 전 구간에는 원문 전송과 Discord 수신도 포함됩니다. 원문 자체가 늦게 나타나는 경우에는 **최근 전송 시간…**도 함께 확인해야 합니다.

### 최근 번역 시간으로 확인하기

번역 시도 뒤 **설정 → 최근 번역 시간…**을 엽니다. 이전 원문 전송용 **최근 전송 시간…**과 별개입니다. 시간 기록에는 원문·메시지 ID·채널·URL·키가 없으며 현재 연결의 최근 한 건을 메모리에만 보관합니다.

채팅창의 전송·번역 측정 시간은 기본으로 숨깁니다. 보려면 기본 설정의 **채팅창에 지연 시간 표시**를 켜세요. **연결 완료·준비 중·새 채팅 기다림·번역 ON/OFF 같은 정상 안내는 이 옵션과 관계없이 채팅창에서 숨깁니다.** 설정의 연결 상태에는 안내를 남기며, 오류와 **최근 번역 시간…**의 상세 기록은 계속 확인할 수 있습니다.

| 표시 | 의미 |
|---|---|
| 전체 | 번역 대기열에 넣은 시점부터 UI가 결과를 꺼낸 시점까지. 그 이전의 Discord 수신·UI 대기, 실제 화면 그리기와 친구 PC의 수신은 제외 |
| 번역 대기열 | 두 작업자 중 하나가 해당 작업을 시작할 때까지 기다린 시간 |
| API 전체 | API 요청 준비·전송·서비스 대기·응답 읽기·검증. 모델 계산만의 시간은 아님 |
| 웹후크 대상 채널 확인 | 번역을 게시하기 전에 웹후크가 같은 채널을 가리키는지 확인하는 GET |
| 번역 게시·저장 확인 | Discord가 번역 메시지를 저장했다고 확인한 POST 응답까지 |
| UI 이벤트 전달 | 작업 완료 후 UI에서 결과를 꺼낼 때까지 |
| 처리 방식 | OpenAI는 요청한 표준/Fast와 서버가 보고한 실제 등급. 다른 제공사는 **처리 방식: 제공사 기본값**. 재사용이면 새 API 요청이 없었다고 표시 |

API 성공 응답에서는 **Windows 전송 호출 / Windows 응답 수신 호출 / Windows 본문 읽기**를 표시합니다. 각 Windows 함수가 돌아올 때까지 걸린 시간이며 순수 업로드·네트워크·모델 계산 시간으로 나눈 값이 아닙니다. 전송에 시간이 몰리고 응답 수신·읽기가 0ms여도 모델 처리 시간이 0이라는 뜻은 아닙니다. 이미 응답을 받았거나 1ms 미만인 호출은 0ms로 표시될 수 있습니다. Windows의 호출 의미는 [WinHttpSendRequest](https://learn.microsoft.com/en-us/windows/win32/api/winhttp/nf-winhttp-winhttpsendrequest)와 [WinHttpReceiveResponse](https://learn.microsoft.com/en-us/windows/win32/api/winhttp/nf-winhttp-winhttpreceiveresponse)에 나와 있습니다.

서버 처리 시간과 추론 토큰은 서비스가 제공한 경우에만 표시하며 없으면 `미보고`로 표시합니다. 서버 처리 시간은 API 전체의 일부이므로 더해서 합산하지 않습니다. 예를 들어 **전체 2,729ms, API 2,050ms, 채널 확인 276ms, 게시 355ms, UI 47ms**인 기록에서 서버가 **1,397ms**를 보고했다면 API와 서버 처리 시간을 합쳐 3,447ms로 계산하지 않습니다. API와 서버 값의 차이인 약 653ms도 순수 네트워크 왕복 시간으로 확정할 수 없습니다. 이 예는 사용자가 제공한 이전 측정값의 해석이며 이 배포본의 속도 개선 실측값이 아닙니다.

대기열이 길다면 연속 메시지 처리량을, API 전체가 길다면 모델·서비스·네트워크 구간을, 게시가 길다면 Discord 구간을 구분해 볼 수 있습니다. 한 번의 숫자는 이후 속도를 보장하지 않습니다. [OpenAI 지연 최적화 안내](https://developers.openai.com/api/docs/guides/latency-optimization.md)를 참고하세요.

### OpenAI의 일본이나 한국 서버를 선택할 수 있나요?

2026-11-12의 [OpenAI 공식 지역 지원 문서](https://developers.openai.com/api/docs/guides/your-data.md)는 다음과 같이 구분합니다. 데이터의 저장 위치와 모델이 실제로 계산하는 위치는 별개입니다.

| 지역 | 공식 지원 | 사용할 때 필요한 조건 |
|---|---|---|
| 일본 `jp.api.openai.com` | `gpt-6-luna`의 지역 내 추론 지원 | 활성 Zero Data Retention(ZDR), 일본 지역 프로젝트, Standard 종량제 처리. MAM만으로는 부족하며 현재 이 조합은 Fast를 지원하지 않음 |
| 한국 `kr.api.openai.com` | 지역 내 저장 지원, 지역 내 추론 미지원 | 한국 주소가 있다는 이유로 모델 계산도 한국에서 한다고 볼 수 없음 |

미국 외 지역의 데이터 지역 설정에는 승인과 계약 조건이 있고 해당 지역 처리의 추가 요금도 있습니다. 누구나 주소 하나를 바꾸면 바로 일본 추론을 쓰는 구조가 아니며, 가까운 지역이라고 모든 지연이 사라진다는 보장도 없습니다. Sideglow의 **OpenAI** 모드는 기존 `api.openai.com` 주소로 고정되어 있으며 지역 선택이나 키 자동 전환 기능은 넣지 않았습니다. **OpenAI 호환 서비스**의 주소 입력은 Chat Completions 서비스용이며 공식 OpenAI Responses의 지역 선택 기능이 아닙니다.

## 오류가 날 때

| 상태 | 확인할 것 |
|---|---|
| API 키가 없거나 열리지 않음 | 같은 Windows 계정인지 확인하고 AI 번역 설정에서 키를 다시 입력·저장합니다. 다른 PC로 암호화된 설정 파일만 복사해서 사용하지 마세요. |
| 인증·권한·모델·잔액 오류 | 선택한 제공사의 키·모델 접근·사용 가능 금액을 확인합니다. OpenAI Fast를 켠 경우 모델·계정의 지원 여부도 확인합니다. 오류 수정 후 기본 설정을 다시 저장하거나 번역 ON/OFF를 껐다 켭니다. |
| 제공사·주소와 저장된 키가 다름 | 원하는 **API 제공사 → API 기본 주소**를 먼저 정하고 그 연결용 키를 입력합니다. 모델만 바꿨다면 제공사와 주소가 기존 값인지 확인합니다. |
| 호환 서비스의 요청 형식 오류 | HTTPS 기본 주소에 `/chat/completions`를 중복 입력하지 않았는지, 선택한 모델이 Bearer 인증·Chat Completions·`response_format: json_object`·`max_tokens`를 지원하는지 확인합니다. [제공사별 조건](API-PROVIDERS.md)을 참고하세요. |
| API 요청 제한 / 일시 오류 | 안내된 대기 동안 일부 메시지는 건너뛸 수 있습니다. 유료 요청을 자동 반복하지 않습니다. 원문은 그대로 유지됩니다. |
| 번역 대기 한도 | 메시지 유입이 처리 속도보다 빠릅니다. 담당 PC를 여러 대 켜는 대신 유입량·모델을 검토하세요. |
| 번역 전송 실패 | 설정한 웹후크가 같은 채널을 가리키고 여전히 유효한지 확인합니다. 결과가 불확실한 POST는 자동 재전송하지 않습니다. |
| 새 채팅도 번역되지 않음 | 담당 PC가 그 채널의 탭을 선택했는지, 일반 실행·Discord 수신 연결·공용 번역 실행·올바른 입력 웹후크가 준비됐는지 확인합니다. 비활성 탭, 예전 기록, 다른 봇 글은 새 번역 대상이 아닙니다. |

모델이 JSON 형식을 지키지 못하거나 요청한 언어 방향과 다른 결과를 주면 그대로 채널에 게시하지 않습니다. 서비스의 원시 오류 본문·API 키·채팅 원문은 오류 안내에 넣지 않습니다.

## 키 저장과 구현 범위

키는 `%LOCALAPPDATA%\Sideglow\settings.json`에 Windows DPAPI로 보호한 값만 저장합니다. 설정을 읽거나 번역 설정 창을 여는 것만으로 키를 복호화하지 않습니다. 이 보호는 같은 Windows 계정으로 실행되는 악성 프로그램까지 격리하지는 않습니다. 프로그램에 공용 API 키를 넣어 배포하지 마세요.

기존 설정 폴더를 자동으로 찾거나 옮기지 않습니다. 기존 키를 계속 쓰기 위한 수동 이름 변경과 초기화 절차는 [저장 폴더 안내](SETUP.md#저장-폴더-변경과-초기화)를 따르세요. 초기화하면 API 키를 다시 입력해야 합니다.

OpenAI·Anthropic·Gemini 모드는 각 공식 HTTPS 주소로만 보내고, OpenAI 호환 서비스는 직접 입력한 HTTPS 기본 주소로 보냅니다. 리다이렉트는 따라가지 않습니다. 키를 제공사·주소와 묶어 보호 저장하고 실행 직전에 다시 확인합니다. OpenAI Responses 요청에만 `store:false`를 지정하며 다른 제공사의 데이터 보존을 같은 옵션으로 제어한다고 가정하지 않습니다. **이 옵션이 OpenAI 측의 모든 보존 정책을 없앤다는 뜻은 아닙니다.** OpenAI 프로젝트의 조건은 [공식 데이터 안내](https://developers.openai.com/api/docs/guides/your-data.md), 다른 서비스의 보존·학습·이용 조건은 해당 제공사 문서를 확인하세요.

이번 버전은 OpenAI Responses, OpenAI 호환 Chat Completions, Anthropic Messages, Gemini GenerateContent를 구현했습니다. Anthropic의 조직 전체 키에 필요한 추가 workspace 헤더와 Gemini의 Vertex AI IAM 인증, 임의 사용자 정의 헤더, 여러 제공사의 자동 선택·실패 시 전환은 지원하지 않습니다. Papago·DeepL·Google 번역 웹페이지 자동 조작, 비공식 내부 요청, 로컬 번역 모델, 개인 화면에서만 수행하는 별도 번역 모드도 구현하지 않았습니다. 기존 중계 모드에서는 AI 번역 담당 기능을 켤 수 없습니다.

타사 API 키를 사용한 실제 호출은 이번 작업에서 하지 않았습니다. 공식 규격에 맞춘 요청과 정상·실패 응답 fixture로 검증했으며, 실제 계정의 인증·모델 권한·번역 품질·지연까지 확인한 것은 아닙니다. 코어 모의 테스트·Windows 교차 빌드 범위와 실환경 미검증 항목은 [VALIDATION.md](VALIDATION.md)에 기록합니다. 실제 Windows UI·Discord·번역 API 계정으로 완료한 실사용 시험이라고 해석하면 안 됩니다.
