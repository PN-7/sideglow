### 당시 기능별 확인 범위

- **닉네임:** 현재·이전 버전의 웹후크 표시 접두부를 오버레이 표시 단계에서만 제거합니다. `☆` 같은 실제 닉네임, 원본 author 값·메시지 식별자는 보존합니다. 일반 사용자 닉네임에는 동일 문자열이 있어도 제거하지 않습니다.
- **시간:** RFC3339의 날짜·시각·명시적 UTC offset을 검증하고 FILETIME으로 변환하는 휴대 가능한 테스트 3개를 통과했습니다. Windows에서는 동적 시간대 API를 사용합니다. Windows 전용 현지 시간 변환 테스트는 대상 컴파일·정적 검사에 포함했으며 실제 실행하지 않았습니다.
- **개인별 로마자 옵션:** 기본 OFF·설정 저장/격리·연결 코드 제외, 전송 대기열에서 개인 설정 캡처, 서버가 관리하는 작성자 이름 보존, 미체크 상태의 예약 이름 오인 방지, 동일 메시지 재전송 구분을 확인했습니다. 번역기는 신뢰하는 웹후크의 표시를 읽으며 옵션별 캐시·중복 작업을 분리합니다. 일반 Discord 또는 표식 없는 구버전 메시지는 추가 로마자 지침을 사용하지 않습니다.
- **제공사 요청/응답:** OpenAI 기존 회귀 테스트 13개 및 새 provider mock 테스트 8개를 통과했습니다. 인증 헤더 분리, 같은 번역 지침·언어 방향, 완료된 정상 출력, 거절·잘림·tool call·차단·잘못된 JSON·응답 상한을 확인합니다. 실제 모델의 번역 품질이나 공급자의 계정별 기능을 확인한 결과는 아닙니다.
- **Gemini 출력 예산:** 정확히 확인한 13개 텍스트 모델 ID에만 지원되는 낮은 thinking 설정을 보내고 4,096토큰까지 허용합니다. 미등록·이미지 변형 모델에 추측한 설정을 보내지 않는 회귀 테스트를 추가했습니다. 상한에 걸린 응답은 계속 게시하지 않습니다.
- **주소·키:** endpoint 테스트 17개와 설정 테스트 35개 안에서 공식 주소 고정, HTTPS 주소 정규화, Gemini 모델 경로 제한, 키와 제공사/주소의 결합, 복호화 전·후 결합 검사, 이전 OpenAI 키 제한, 모델 변경 시 키 유지, 암호화 실패 시 원래 상태 보존을 확인했습니다. DPAPI는 순수 로직 테스트에서 모의 함수로 대체했습니다.
- **설정 UI:** 제공사 선택과 주소 입력을 추가했고 Fast/프리셋은 OpenAI에서만 활성화합니다. 새 영역과 기존 컨트롤 간 배치 및 저장/취소 경로를 코드로 검토하고 Windows 대상으로 컴파일했습니다. 실제 화면 조작 결과로 표시하지 않습니다.

제공사별 지원 조건과 등록 절차는 [API-PROVIDERS.md](API-PROVIDERS.md), 개인별 로마자 옵션은 [AI-TRANSLATION.md](AI-TRANSLATION.md)에 있습니다. 옵션을 전달하는 송신자와 공용 번역을 실행하는 PC가 모두 preview.7이어야 하며, Node 중계를 쓰는 경우 중계 코드도 갱신합니다.

### 당시 실제 실행하지 않은 항목

Windows GUI·IME·게임·현지 시간대 API·DPAPI·WinHTTP의 실제 실행과 실계정 Discord 전송, OpenAI·OpenAI 호환·Anthropic·Gemini의 실제 API 호출은 수행하지 않았습니다. 사용자의 앞선 응답 시간 시험과 이번 검증을 혼동하지 않으며, 이번 수정에서 별도 지연 측정을 추가하지 않았습니다.

OpenAI 호환 모드는 Bearer 인증과 Chat Completions의 `messages`, `max_tokens`, `response_format: json_object`를 받는 서비스·모델을 대상으로 합니다. 호환 이름을 사용하는 모든 API의 성공을 보장하는 범위는 아닙니다. Windows 실행 파일을 교차 빌드한 사실도 실제 Windows UI·외부 계정 호출 검증과 구분합니다.

#### 이번 변경의 검증과 코드 검토

##### 기존 데이터와 이전 형식 호환

- 당시 기존 저장 경로와 `Local\WhisperOverlay.Desktop.v1` 중복 실행 방지 식별자를 유지했으며, 로그인·DPAPI 데이터의 위치와 보호 형식을 바꾸지 않았습니다. 실행 중인 창 찾기는 현재·이전 버전의 창 클래스를 모두 조회합니다. 실제 Windows 중복 실행·기존 DPAPI 복호화는 실행하지 않았습니다.
- 새 `SIDEGLOW1:`/`Sideglow connection` v1 내보내기와 기존 `WHISPER1:`/`Whisper connection` v1 가져오기를 검사했습니다. 고정된 이전 fixture를 공개 가져오기 경로로 처리해 기존 개인 설정·비밀정보 보존, 가져온 연결의 공용 번역 OFF, 새 이름으로 재내보내기를 확인합니다. 접두부·JSON 형식 혼합과 지원하지 않는 버전은 거부합니다.
- 이전 버전의 번역 링크를 고정 fixture로 읽고, 새·기존 헤더/태그 혼합은 거부하는 테스트를 추가했습니다. **Sideglow가 이전 형식을 읽는 호환입니다. 구버전 앱이 새 코드와 새 번역 묶기 형식을 지원한다는 뜻은 아닙니다.** 친구들도 새 버전으로 맞추도록 문서에 안내합니다.
- OpenAI 번역 프롬프트·모델·처리 등급·호출 수·동시 작업자·캐시·시간 측정 정책은 변경하지 않았습니다. 지연 개선 또는 악화의 실측 결과가 아닙니다.

##### 라이선스와 출처

- MPL 2.0 원문을 Mozilla 공식 배포와 대조했습니다. 이번 공개본에는 자체 코드의 MPL 적용 범위를 명시하며, 공개 전 개발 패키지의 프로젝트 자체 MIT 고지를 현재 라이선스로 동봉하지 않습니다. 외부 구성 요소의 원래 고지는 유지하며 MPL 헤더를 덮어쓰지 않았습니다.
- 외부 crate 21개의 공식 압축 파일 SHA-256이 Cargo.lock과 일치하고, 동봉 라이선스 파일 42개가 해당 원본과 바이트 단위로 일치합니다. 실제 Rust 1.99.1·MinGW 12.0.0·GCC 14.2 빌드 환경의 고지를 대조하고 MinGW 런타임 전용 고지도 추가했습니다.
- 원본 소스 inventory, crate·런타임 비교 자료, 확인 가능한 문서 URL과 조사 한계는 [PROVENANCE.md](PROVENANCE.md)에 있습니다. 현재 확인한 의존성에서 MPL 적용을 막는 충돌은 발견하지 못했습니다. **전체 과거 참고 이력 복원, 전 세계 소스 유사성 검사나 모든 코드의 독립 작성 보증을 뜻하지 않습니다.**
- 배포 ZIP에 실행 파일에 대응하는 수정 가능한 프로젝트 소스와 빌드 파일·원래 고지를 함께 포함합니다. 자세한 범위는 [LICENSING.md](LICENSING.md)를 참고하세요.
- 공개 전 고지 정리에서는 문서·메타데이터 10개만 수정했습니다. 기존 프로젝트 자체 MIT 고지 파일을 제외한 소스 구성에 수정본을 적용해 삭제된 파일 참조, 상대 문서 링크, JSON 구문 및 압축 파일의 경로·내용을 확인했습니다. 프로그램 소스·외부 라이선스·실행 파일의 변경이나 재빌드는 없으며, 이 문서의 컴파일·단위 테스트 수치는 앞서 완료한 빌드의 결과입니다.

#### 이전 수정의 유지와 회귀 검토

##### Enter/Esc 해제 후 게임 복귀

- 기존 전송 경로는 EDIT의 Enter key-down에서 전송 메시지를 게시한 뒤 곧바로 게임을 전면으로 돌렸습니다. 물리 키가 아직 눌린 상태에서 게임이 다음 반복·해제·눌림 상태를 받을 수 있는 경로를 확인했습니다. 실제 해당 게임이 어떤 입력 API로 반응했는지는 이 환경에서 확인하지 않았습니다.
- 전송 큐 등록 시점은 유지합니다. 빈 Enter·데모 전송·정상 큐 등록·취소에서만 복귀를 예약하고, Enter/Esc의 `GetKeyState`와 `GetAsyncKeyState`가 모두 해제될 때까지 자체 창을 유지합니다. 입력창에서 실제 WM_KEYUP을 처리한 뒤 완료 메시지를 게시하며, 기존 UI 타이머는 보조 경로입니다.
- 상태 테스트 5개는 큐와 물리 해제 순서 차이, Enter/Esc 동시 누름, 이전 해제 뒤 새 누름, 원래 창 보존, 포커스 변경·명시 취소와 늦은 해제, 이미 해제된 요청의 한 번만 완료를 검증합니다. UI 연결 소스 검토에서는 실제 key-up을 받기 전에 EDIT를 비활성화하지 않는지, User32 호출 전에 상태가 해제되는지 확인했습니다.
- 즉시 전송 큐 등록 실패·큐 한도 초과는 복귀를 예약하지 않습니다. 나중에 도착한 네트워크 전송 실패의 초안 복구는 기존 정책을 유지합니다. IME 조합 확정 Enter는 전송 메시지를 게시하지 않으며, 입력창 열기의 실제 WM_HOTKEY 경로와 `hotkey.rs`의 동작은 이전 버전과 동일합니다(라이선스 헤더만 추가).
- 새 타이머·스레드·전역 훅·합성 키 입력·추가 네트워크 요청을 만들지 않습니다. 실제 Windows 게임·IME 포커스 전환은 실행하지 않았습니다. [키보드 입력·포커스](https://learn.microsoft.com/en-us/windows/win32/inputdev/about-keyboard-input), [GetMessage 처리 순서](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getmessagew), [GetKeyState](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getkeystate) 문서를 근거로 검토했습니다.

##### 로마자 일본어 번역 지침

- 기존 모델 요청은 A/B/other 판별만 요청했습니다. 특히 A=일본어에서 로마자 일본어가 other로 잘못 분류되면 일본어로 번역될 수 있습니다. 실제 사용자가 겪은 메시지의 모델 응답 태그를 확인한 것은 아니므로 그 사례의 확정 원인이라고 기록하지 않습니다.
- 문자 체계와 언어를 구분하고, 일본어가 언어 쌍에 있을 때는 명확한 로마자 일본어를 일본어로 판별해 상대 언어로 뜻을 번역하도록 요청합니다. 단순한 가나·한자 재표기로 끝내지 않으며 영어 문장 속 일본 이름과 모호한 짧은 토큰의 오분류를 피하도록 명시합니다.
- 새 테스트 1개는 일본어 조합에만 정책을 추가하는지, A/B 순서·대소문자·ja-JP 코드, 원문·용어집의 분리와 무수정 전달, 기존 응답 스키마 유지를 확인합니다. 기존 응답 방향 테스트도 두 순서와 지역 코드로 확장했습니다.
- 위 검사는 요청 구성과 모의 응답의 로컬 방향 처리 검증입니다. **실제 모델의 로마자 판별률이나 번역 품질을 확인한 테스트가 아닙니다.** 실계정 API 호출이나 자동 재번역은 수행하지 않았습니다. 추가 판별 API·로컬 사전·ASCII 강제 분류·작업자·재시도도 추가하지 않았습니다.


##### 일본어 초기 안내와 글꼴 방향

- 기존 코드는 글꼴 선택창에 세로쓰기용 `@` 글꼴을 허용하고, 채팅이 없을 때의 안내문에도 사용자가 고른 채팅 글꼴을 사용했습니다. 첨부된 일본어 글리프만 90도 회전한 화면은 이 경로의 문제와 일치하지만, 사용자 PC의 실제 선택값이나 글꼴 매핑 결과는 확인하지 않았습니다.
- `CF_NOVERTFONTS`로 선택창 목록에서 세로 글꼴을 제외하고, 설정 로드·저장과 실제 글꼴 생성에 가로쓰기 이름 보정을 적용했습니다. 회전 각도는 0을 유지합니다. 첫 안내문에는 헤더·푸터와 같은 Segoe UI 계열의 별도 글꼴을 본문 설정 크기로 사용합니다.
- 자동 테스트는 일본어·한국어·영문 글꼴 이름의 보정, 일반 이름 보존, 잘못된 빈 이름 거부, 기존 언어·크기·게임·투명도·보호된 API 키를 유지하는 설정 이행을 확인했습니다. 별도 글꼴 핸들의 초기화·재생성·해제와 DC 상태 복원도 소스로 검토했습니다.
- 실제 Windows 일본어 표시·글꼴 선택창·DPI 화면은 실행하지 않았습니다. Microsoft의 [세로쓰기 글꼴 설명](https://devblogs.microsoft.com/oldnewthing/20120719-00/?p=7093/)과 [CHOOSEFONTW](https://learn.microsoft.com/en-us/windows/win32/api/commdlg/ns-commdlg-choosefontw)를 구현 근거로 사용했습니다.

##### Discord 인증 오류와 테스터 안내

- 제공된 기존 일본어 오류는 브라우저 OAuth 콜백의 `invalid_scope` 또는 `unauthorized_client`에서 발생하는 공통 문구였습니다. 토큰 교환·RPC 인증·채널 읽기·웹후크 검증 전에 표시되는 경로입니다. 이전 화면만으로 둘 중 어느 코드였는지는 복원할 수 없습니다.
- 두 오류와 `access_denied`를 구분하고 인증 단계·허용된 오류 이름·HTTP 상태만 표시하도록 변경했습니다. 원격의 임의 오류 설명·주소·코드·토큰은 반사하지 않습니다. 자동 테스트로 정상 구분과 악성·알 수 없는 오류 문자열의 비노출을 확인했습니다.
- 세 언어의 7개 기존 메시지를 갱신하고 메시지 ID를 유지했습니다. 새 키·라이브러리·백그라운드 작업·요청은 추가하지 않았습니다.
- 공식 문서를 확인해 [SETUP.md](SETUP.md)에 운영자의 App Testers 초대와 친구의 등록 이메일 수락·동일 계정 재로그인 절차를 추가했습니다. 실제 친구 계정의 테스터 상태나 Discord 앱 권한은 확인하지 않았으며, 코드 수정이 해당 권한을 부여하지 않습니다.


##### 연결 코드 — 자동 테스트

- `SIDEGLOW1:<base64url>.<CRC32>` 코드의 내보내기·가져오기 왕복과 이전 `WHISPER1:` 코드 가져오기, 채널 링크 정규화, 빈 웹후크를 사용하는 수신 전용 연결을 확인했습니다. 기존 JSON 파일 형식은 여전히 웹후크를 요구하며 파일 저장·불러오기 회귀 테스트도 통과했습니다.
- base64url의 표준 예제와 CRC-32/ISO-HDLC의 알려진 값을 확인했습니다. 패딩·잘못된 문자·사용하지 않는 마지막 비트가 0이 아닌 인코딩을 거부하며, 같은 바이트와 유효한 CRC로 해석될 수 있는 비정규 인코딩도 차단합니다.
- 유효한 코드의 각 위치에서 잘린 입력, payload 변경, 확인값 변경, 지원하지 않는 접두부·버전, 잘못된 JSON·UTF-8, 누락·중복·알 수 없는 필드를 검사했습니다. 이스케이프된 이름으로 같은 JSON 필드를 중복하는 경우도 거부합니다.
- ASCII 공백·줄바꿈·VT를 허용하고 Unicode 공백·NUL 등 지원하지 않는 문자를 거부합니다. 원문 **32KiB**, 디코딩 결과 **16KiB**, 개별 연결 링크의 기존 상한을 확인했습니다. 정규화된 텍스트와 디코딩 버퍼의 길이는 할당 전에 제한합니다.
- 유효한 확인값을 다시 붙여도 허용하지 않은 도메인·HTTP·사용자 정보가 섞인 주소·DM/숫자 채널·웹후크 경로 조작·쿼리 주입을 거부하는지 검사했습니다. 오류 메시지에 코드·웹후크 비밀값·외부 주소가 반사되지 않는지도 확인했습니다.
- 디코딩한 payload를 대조해 형식·버전 메타데이터 외에 앱 ID·채널 링크·웹후크만 포함하는지 확인했습니다. UI 언어·게임 경로·중계 키·번역 API 키·모델·언어·용어·다른 탭 정보를 바꿔도 공유 코드가 달라지지 않습니다.
- 가져온 프로필 적용 뒤 개인 설정과 기존 키가 유지되고, 가져온 연결의 번역 실행은 꺼지는지 검사했습니다. 앱 ID가 달라지면 모든 탭의 기존 번역 실행 선택을 끕니다. 원래 설정 객체는 수정하지 않습니다.

코드는 되돌릴 수 있는 인코딩이며 암호화·발신자 인증이 아닙니다. CRC는 복사 손상 확인용입니다. 위 검사는 실제 Discord 접근 권한이나 웹후크 대상 채널의 일치를 증명하지 않으며, 그 확인은 기존 연결·전송 단계에 남아 있습니다. 사용 흐름은 [CONNECTION-CODE.md](CONNECTION-CODE.md)를 참고하세요.

##### 연결 공유 창 — 소스 검토

- 버튼과 Ctrl+V의 붙여넣기는 같은 제한된 처리 경로를 사용합니다. 클립보드 글로벌 메모리 크기를 UTF-16 기준 **65,538바이트 이하**로 검사하고, 그 범위 안에서 종료 문자와 문자 유효성을 확인합니다. UTF-8 변환 결과에도 코드 원문 상한을 적용합니다. 입력 컨트롤 역시 확인한 길이로 직접 버퍼를 할당합니다.
- 클립보드에서 받은 메모리는 해제하지 않고 잠금만 풉니다. 직접 할당한 복사용 메모리는 실패하면 해제하고, `SetClipboardData`가 성공하면 Windows에 소유권을 넘깁니다. 잠금을 푼 뒤 클립보드를 닫도록 수명 순서를 확인했습니다.
- 코드 입력은 기본 가림이며 사용자가 표시할 수 있습니다. 미리보기에는 앱 ID·채널·웹후크 포함 여부만 표시하고 웹후크 비밀값은 표시하지 않습니다. 복사한 코드는 Windows 클립보드의 일반 텍스트이며 가림 표시는 암호화가 아닙니다.
- 모달 상태는 창 파괴와 메시지 루프 종료까지 유지합니다. `WM_QUIT`은 상위 루프에 다시 게시합니다. 코드 창의 취소·닫기 또는 소유 창의 파괴는 가져온 프로필을 반환하지 않으며, 파괴된 부모의 초안을 다시 참조하지 않습니다.
- **설정에 채우기**는 로컬 초안만 반환합니다. 호출자는 현재 탭의 ID·이름을 보존하고 기존 중복 목적지 검사 뒤에 초안을 교체합니다. 미전송 대화 초안 보호는 이후 기존 저장·로그인 적용 경로에서 수행합니다. 코드 가져오기가 로그인·메시지 전송·번역 실행을 시작하지 않습니다.
- 연결 안내 창에서 **설정에 채우기**까지 마친 뒤 안내를 닫으면 그 값은 메인 설정 초안에 남습니다. 메인 **저장** 또는 명시적인 **Discord 로그인/연결** 전에는 실제 연결에 적용되지 않습니다. 메인 취소는 미저장 초안을 버리며, 이미 별도 로그인 동작으로 저장한 변경을 소급 취소하지는 않습니다.
- 공유 코드 생성·검증은 사용자 조작 때 수행하며 파일 I/O·네트워크·추가 작업자·클립보드 감시를 추가하지 않습니다.

이 항목은 **소스 검토와 Windows 대상 컴파일 범위**입니다. 실제 Windows 클립보드 소유권 이전, Ctrl+V, 가림/표시, 창 닫기나 부모 종료 동작을 실행한 결과가 아닙니다.

##### 언어 파일과 오류 대체

- 내장 한국어 문구를 기본값으로 유지하고 실행 파일 옆의 `locales/{언어 ID}.json`을 읽습니다. 사용자 언어 ID는 길이와 문자 범위를 제한하고 경로 구분자·확장자·Windows 예약 장치명을 거부합니다.
- 한국어 파일이 없을 때는 내장 한국어를 사용합니다. 선택한 다른 파일이 없거나 전체 형식·언어 ID가 잘못되었으면 한국어로 대체하고 안전한 경고를 제공합니다. 경고에 원본 JSON·파일 경로·파서 오류 내용을 넣지 않습니다.
- 일부 항목만 누락되거나 빈 문자열·NUL·유효하지 않은 자리표시자를 포함하면 해당 항목만 기본 문구를 사용합니다. 중복 JSON 키는 파일 전체 오류로 처리합니다.
- 동적 문구는 자리표시자 이름과 등장 횟수를 원문과 대조합니다. 값의 순서 변경은 허용하지만 변수 추가·삭제·이름 변경은 거부합니다. 삽입된 사용자 문장에 `{name}` 같은 내용이 있어도 다시 해석하지 않습니다. 정적 문구의 중괄호는 일반 문자로 유지합니다.
- 한국어·영어·일본어 각 파일의 **752개 키**를 실제 생성된 기본 정의와 대조했습니다. 연결 공유 창과 신규 오류 문구도 세 언어에 포함합니다. 검사에서는 기본 문구로 조용히 대체된 항목이 없는지도 확인합니다. 이 검사는 번역의 문맥·자연스러움이나 Windows 화면에서의 문구 길이를 보장하는 시각 검증은 아닙니다.
- 추가 언어 선택 목록은 파일명만 확인합니다. 목록을 표시하려고 모든 언어 파일의 내용을 읽지 않습니다. 사용자 파일의 이름·내용·대체 동작은 로컬 임시 파일 테스트로 확인했습니다.

##### 자원 사용과 문자열 수명

- JSON 파일 읽기·해석은 프로그램 시작과 저장된 화면 언어의 명시적 변경에만 수행합니다. **매 프레임 파일 읽기·JSON 해석·파일 감시·추가 작업 스레드·네트워크 요청은 없습니다.** 같은 언어 파일을 수정한 뒤에는 재시작하거나 다른 언어로 저장한 후 다시 선택하여 로드합니다.
- 평상시에는 생성된 문구 ID로 준비된 테이블을 조회합니다. 반복 표시하는 정적 문구의 UTF-16과 끝의 NUL은 필요한 시점에 한 번 만들어 재사용합니다.
- 기본 문구와 선택한 언어의 항목은 `Arc`로 관리합니다. 언어를 읽는 동안에는 이전 카탈로그·입력 바이트·파싱 맵·새 카탈로그가 일시적으로 함께 존재할 수 있습니다. 교체 후 임시 맵과 사용하지 않는 이전 항목은 해제되며, 호출 중인 UTF-16 참조는 해당 호출이 끝날 때까지 유효합니다.
- 네 독자가 캐시를 사용하는 동안 128회 카탈로그를 교체하고, 읽기가 끝나면 이전 항목이 남지 않는지 검사했습니다. 잠금이 오염된 경우에도 실제 읽기·교체 경로가 복구되는지 검사했습니다. 이 테스트는 전역 언어 상태를 변경하지 않습니다.
- 파일 1MiB, 문구 16KiB, 메시지 객체 4,096개, 언어 선택 항목 64개, 컴파일된 템플릿 조각 256개로 입력 규모를 제한합니다. 많은 이스케이프 중괄호가 임시 자료구조를 과도하게 늘리는 경우도 거부합니다.

##### 저장·취소와 기존 기능의 경계

- 화면 언어는 `settings.ui_language`에 저장하며 AI 채팅 번역의 `language_a`·`language_b`와 구분합니다. 기존 설정 파일에는 기본값 `ko`를 적용합니다.
- 설정 목록에서 언어를 바꾸는 것만으로 현재 언어를 바꾸지 않습니다. 기본 설정의 **저장**에서 검증·설정 파일 저장이 성공한 뒤 언어를 적용합니다. **취소·닫기**는 기존 언어를 유지합니다. 모양 미리보기와 별도의 로그인 안내를 통해 미저장 언어 선택이 적용되지 않도록 코드 경로를 확인했습니다.
- 언어만 바꿀 때 연결 목적지 비교와 `ConnectionIdentity`·번역 `Spec`의 동일성 판단이 유지되는지 코드로 확인했습니다. 화면 언어는 이들 연결·번역 설정 식별값에 포함하지 않습니다. 실제 Discord 연결을 유지한 채 언어를 변경하는 실환경 검증은 수행하지 않았습니다.
- 언어 변경이 기존 전송·연결 오류를 지우지 않도록 상태 표시를 보존합니다. 이미 생성된 이벤트 문장은 발생 당시의 언어로 남을 수 있으며 새 문구부터 현재 언어를 사용합니다. 채팅 원문·사용자 지정 탭 이름·API 모델 ID와 Windows 공통 대화상자의 시스템 문구는 이 언어 파일로 바꾸지 않습니다.
- OAuth 승인 후 브라우저에 보여 주는 번역 문구의 `&`, `<`, `>`를 HTML 텍스트에 맞게 변환합니다. 번역 파일의 문구가 링크나 태그로 삽입되는 것을 막는 테스트를 추가했습니다. 이 변경은 OAuth 권한·승인 절차를 추가하거나 우회하지 않습니다.

Save/Cancel, 상태 보존, 연결 동일성의 위 설명은 코드 검토 및 관련 순수 로직 테스트 범위입니다. 실제 Windows 설정 화면을 조작한 결과로 표시하지 않습니다.

#### 실제로 실행하지 않은 범위

- **Windows 화면·클립보드·설정:** 세 언어의 문구 잘림·DPI·시스템 글꼴, 실제 복사·붙여넣기·가림 표시, 창 닫기·프로그램 종료, 언어 저장·취소·재실행·사용자 언어 파일 적용은 실환경 확인이 남아 있습니다.
- **게임과 기존 표시 기능:** Alt+Tab·Enter·IME·게임 복귀·클릭 통과·스크롤·대화 만료·전체화면·안티치트 호환성을 실제 게임에서 실행하지 않았습니다. 관련 순수 로직 회귀 테스트를 Windows 화면 실행 결과로 해석하면 안 됩니다.
- **Discord와 API:** 실제 계정의 권한·OAuth 로그인·RPC 수신·웹후크 전송·탭 전환·번역 요청과 지연은 호출하지 않았습니다. 공유 코드는 계정 승인이나 채널 권한을 대신하지 않습니다. 비활성 탭의 과거 메시지 전체 수집·소급 번역도 기존 지원 범위에 포함되지 않습니다.
- **성능:** RAM·CPU·FPS, 초기 언어 로드 시간, 코드 창의 실제 사용량, 게임·Discord 동시 실행 영향을 측정하지 않았습니다. 파일 크기나 구조상 추가 작업이 없다는 사실을 성능 실측값으로 표현하지 않습니다.

이미 제출한 원격 API 요청이나 Discord POST를 언어 변경·탭 전환·번역 OFF로 소급 취소할 수는 없습니다. 기존 전환 전에 시작한 번역 POST가 원래 채널에 늦게 완료될 수 있으며 새 탭으로 돌려 보내지는 않습니다.

위 항목은 실행하지 않은 검증 범위이며 사용자가 반드시 수행해야 하는 설정 절차 목록은 아닙니다. 이번 작업에서 실계정 Discord/API 호출·메시지 게시·실제 API 과금은 발생시키지 않았습니다.
